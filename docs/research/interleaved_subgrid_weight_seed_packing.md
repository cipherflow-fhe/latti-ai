# 卷积权重的交错子网格种子打包

本文记录用户提出的参数密文压缩方案：将原本沿空间维度重复存放的多个权重向量，
交错存入一条种子密文的不同空间子网格；运行时以公开掩码提取指定子网格，
再通过旋转与相加恢复空间重复布局。

本文描述设计及基于当前配置的估算，不代表代码已经实现或完成 CKKS 性能验证。

## 1. 适用对象与基本思路

当前 multiplexed 卷积的一个权重向量，在各通道位置具有对应的系数，
这些系数沿 feature 的空间高宽重复。空间边界可能另有卷积 padding 置零。
这里的一个“权重向量”不是单个标量，而是一次现有卷积乘法所需的整条槽向量。

配置空间交错间隔 `(a,b)`，将最多 `a*b` 个这样的权重向量打包到一条种子密文。
逻辑空间位置 `(h,w)` 归属于子网格：

```text
subgrid(h,w) = (h mod a, w mod b)
```

每个子网格保存一个权重向量在该通道位置的系数。此操作保持原有的通道映射，
只复用空间重复区域，不要求所有输入通道能装入一条密文。

例如 `(2,2)` 将 A、B、C、D 四个权重向量交错存放：

```text
A B A B ...
C D C D ...
A B A B ...
C D C D ...
```

图示应在每个通道位置分别理解；不同通道位置的 A 等符号可以代表不同的权重系数。
不足 `a*b` 个权重的最后一条种子，其未分配子网格填零。

## 2. 按需提取与恢复

对目标子网格 `(r,c)`，构造公开二值掩码：

```text
M[r,c](h,w) = 1, 当 h mod a = r 且 w mod b = c
             0, 其他情况
```

该掩码在所有通道位置使用相同的空间选择规则。运行时先计算：

```text
v = rescale(seed * M[r,c])
```

随后仅用旋转与相加，将提取出的周期性子网格复制到全部逻辑空间位置。
例如提取 A：

```text
A 0 A 0 ...       A A A A ...       A A A A ...
0 0 0 0 ...  -->  0 0 0 0 ...  -->  A A A A ...
A 0 A 0 ...       A A A A ...       A A A A ...
0 0 0 0 ...       0 0 0 0 ...       A A A A ...
                  列旋转相加         行旋转相加
```

因此，`(2,2)` 下每个目标权重需要一次掩码乘法及两次旋转。
四个权重全部独立展开，共需四次掩码乘法及八次旋转，乘法深度仍为一层。

若批量生成全部子网格，也可以提取其中 `a*b-1` 个，用降到相同 level 的原种子
减去这些提取结果，得到最后一个子网格，再进行复制。这可少做一次提取掩码，
但需要共享中间结果；独立按需提取不依赖这个优化。

### 2.1 一般交错间隔

下文要求 `a`、`b` 为 2 的幂，且分别整除逻辑空间尺寸 `H`、`W`。
每个目标权重需要：

```text
提取掩码乘法：1 次
额外旋转：log2(a) + log2(b) 次
额外乘法深度：1 层
```

每个方向可采用倍增复制：若初始位置模 `a` 的余数为 `r`，
依次处理 `r` 的低位，在第 `j` 步根据该位选择正向或负向的 `2^j` 位移，
使已经填满的区间最终覆盖一个完整周期。列方向同理。
位移符号须按后端旋转约定转换，不能直接把所有子网格都按同一方向复制。

在物理槽布局 `[B,H,sh,W,sw]` 下：

```text
相邻逻辑列的槽位移：sw
相邻逻辑行的槽位移：sh * W * sw
```

旋转不会改变同一个交错通道子位置；复制应保持原通道映射。
在上述整除与周期条件下，选择适当方向的复制可在各 block 内恢复完整空间布局。

## 3. Level、scale 与卷积边界

若现有卷积使用的权重处于 level `L`，种子以 level `L+1` 保存。
提取掩码经过一次乘法和 rescale 后，权重回到 `L`；后续旋转与相加不消耗乘法 level。
掩码编码 scale 应与所丢弃的模数配合，使展开后的权重保持卷积要求的 scale。

交错间隔增大不会增加提取的乘法深度。较高的种子 level 会增加单条密文的文件体积，
因此实际字节量不会严格按 `a*b` 倍缩小。

对于 1×1 卷积，空间重复恢复后即可作为原权重使用，不需要额外的 kernel 边界掩码。

对于存在 padding 边界的 3×3 等卷积，应在种子中保存未做空间边界置零的权重。
先展开，再施加对应 kernel 的边界掩码；否则被提前置零的系数可能无法通过复制恢复。
若该边界掩码采用普通乘法及 rescale，还需另预留一个 level。
因此，下文 MobileNetV2 的数字只对普通 multiplexed 1×1 卷积应用本方案。

### 3.1 编译器最高 level 无需随参数展开提高

当前参数集的编译器 feature 最高 level 为 9，表示 bootstrap 后供主计算图使用的
level 预算；底层模数链实际支持到 level 24。离线初次加密的参数不经过 bootstrap，
因此可以在 `L+1` 或 `L+2` 加密，完成参数分支的展开后降到原 use-site level `L`。
即使 `L=9`，种子从 10 或 11 开始也无需将主图最高 level 从 9 提高，
也不应因此增加卷积的 activation 路径 level cost。
实现时仍须保证参数节点校验、编码/加密和所需计算密钥支持这些 level，
并且种子 level 不超过底层模数链上限；不能仅凭主图配置为 9 就拒绝高 level 参数。

## 4. 与 runtime_lazy 的结合

建立现有权重索引到 `(seed_id,r,c)` 的映射。
请求一个权重时，加载对应种子，提取目标子网格并恢复空间重复布局，
然后进入现有卷积乘加过程。

每个权重可以独立展开，不必同时生成其他子网格。运行时可缓存种子，
在处理完其对应权重后释放；也可按种子组织访问顺序，避免重复读取文件。
本文旋转统计假设每个目标权重在一次推理中展开一次，不包含重复展开。

所需旋转密钥须支持种子提取后、权重 use-site level 上的复制旋转。
仅改变 `runtime_lazy` 的加载选项不会自动实现此打包，仍需修改离线参数导出、
索引映射及在线权重生成逻辑。

### 4.1 展开操作纳入 score / cost 与动态规划

计算方在线执行的提取掩码乘法、rescale、旋转、相加，以及需要时的边界掩码，
均须纳入对应 level 的操作计数和运行成本，作为编译器 score / cost 与动态规划的依据。
公开 mask 本身不作为加密参数存储计费，但其在线计算不能漏计。
存储成本则按种子数量及实际 `L+1` / `L+2` 计费，替换原完整权重的存储成本。

若由动态规划选择交错间隔，应对每个候选同时评估新增运行成本与减少的存储字节，
并使计数与最终生成的展开图一致。参数分支的额外深度作为独立可行性约束，
无需扣减 activation 的 level 预算。成本校准也应覆盖展开实际使用的 level；
这些是后续实现要求，当前代码尚未集成本方案的展开计费。

## 5. MobileNetV2：256×256 输入的估算

模型与任务配置：

- 模型：[`examples/test_imagenet/model/mobilenetv2.py`](../../examples/test_imagenet/model/mobilenetv2.py)，默认宽度及 1000 类。
- 配置：[`examples/test_imagenet/task/server/nn_layers_ct_0.json`](../../examples/test_imagenet/task/server/nn_layers_ct_0.json)。
- 多项式阶数 `N=65536`，实数槽数 `T=32768`，沿用该配置的 feature level 排程。
- 普通 multiplexed 卷积共 34 层，均为 1×1；已计入现有 periodic 优化，合计 12,496 个权重向量。
- 仅压缩上述普通卷积；大尺寸首层、depthwise、FC、bias 和激活多项式系数保持现有完整参数存储。

设每层有 `P_l` 个权重向量，采用统一间隔 `(a,b)`，则：

```text
种子数量 = sum_l ceil(P_l / (a*b))
额外旋转 = sum_l P_l * (log2(a) + log2(b))
提取掩码乘法 = sum_l P_l = 12,496
```

最后一式按独立提取计算，不使用补集优化。旋转按一次非零位移请求计数，
不直接代表实测耗时或全网络旋转总数。

| 交错间隔 | 普通卷积种子 CT 数 | 额外旋转次数 | 普通卷积权重载荷 | 全部参数密文载荷 |
| --- | ---: | ---: | ---: | ---: |
| 不交错，现有存储 | 12,496 | 0 | 54.36 GiB | 75.15 GiB |
| `(2,2)` | 3,124 | 24,992 | 15.48 GiB | 36.27 GiB |
| `(2,4)` | 1,562 | 37,488 | 7.74 GiB | 28.53 GiB |
| `(4,4)` | 781 | 49,984 | 3.87 GiB | 24.66 GiB |
| `(8,8)` | 200 | 74,976 | 0.99 GiB | 21.78 GiB |

所有这些交错方案的提取乘法深度均为一层。种子数量按层分别向上取整，
不跨层合并。当前这些层的输入高宽均可被表中的交错间隔整除。

以 `(2,2)` 为例，参数密文载荷约为 **38.94 GB（36.27 GiB）**，
比现有约 **80.69 GB（75.15 GiB）** 减少约 **51.7%**。

### 5.1 字节估算口径

使用当前密文序列化的模数实际位宽。对 degree-1 密文：

```text
BytesCT(L) = (L + 21) + (2*N/8) * sum(bit_length(q[j]), j=0..L)
```

`q` 取 `inference/lattisense/frontend/custom_task.py` 中
`N16QP1546H192H32` 参数对应的实际模数。
每层种子载荷按 `ceil(P_l/(a*b)) * BytesCT(L_l+1)` 计算，
已包含种子提高一级的体积开销。

未应用本方案的参数约占 20.79 GiB：

| 参数部分 | 载荷估算 |
| --- | ---: |
| 大尺寸首层卷积权重 | 5.59 GiB |
| depthwise 卷积权重 | 4.86 GiB |
| FC 权重 | 4.67 GiB |
| 各层 bias | 1.50 GiB |
| 激活多项式系数 | 4.17 GiB |

以上是配置推导出的参数密文 payload，未实际生成 bundle；
不包含 `eval_context` 中的公钥、旋转密钥、bootstrap 密钥，
也不包含 manifest、参数文件封装及其他文件。
完整 bundle 的大小需另加这些项目；CKKS 数值精度、实际耗时及密钥大小尚待验证。

## 6. 方案比较与建议

### 6.1 判断标准

该方案同时改变三项成本：

1. 参数存储：种子数量约按 `a*b` 降低，但种子需要在 `L+1` 编码，单条密文变大。
2. 在线算子：每个逻辑权重增加一次公开 mask 乘法、一次 rescale，以及
   `log2(a)+log2(b)` 次复制旋转和若干加法。
3. 工程复杂度：除参数生成外，还要修改 manifest 映射、lazy loader、scale/level
   校验和 cost model。

因此不能只按种子 CT 数量选择间隔。`(8,8)` 虽然表中存储最小，但会把每个普通卷积
的复制旋转增加到 6 次，并将全部 12,496 个权重都变成一次运行时 mask 乘法；对小
feature map 或只执行少量输出通道的层，这个交换并不划算。

### 6.2 候选方案

**方案 A：文档中的独立子网格展开。**

这是最容易验证的通用方案，也是存储收益最高的方案。它适合空间尺寸大、1×1、同一
层的绝大多数权重都会使用的场景。缺点是 mask 乘法和旋转按逻辑权重重复，`(4,4)`
及以上的运行时开销可能超过参数加载节省。

**方案 B：只沿一个方向交错。**

把 `(a,b)` 限制成 `(a,1)` 或 `(1,b)`，仍使用同一套 mask、复制和 seed manifest。
例如 `(2,1)` 只有一次复制旋转，代码只需把二维周期判断退化为单轴判断。存储收益
不如二维交错，但边界、槽位步长和 level 处理更简单，适合作为第一版实际实现。
对于 `H=W=256` 的 1×1 层，建议先评估 `(2,1)` 或 `(2,2)`，不要默认 `(8,8)`。

**方案 C：层内两级共享展开。**

一个 seed 先提取出较大的中间子网格，再从中间结果复制到最终周期。它可以复用
中间结果，降低重复 seed load 和部分调度开销，但不会消除每个最终子网格所需的
mask 选择；如果所有子网格都要使用，公开 mask 乘法数量的总和仍接近 `a*b` 次。
它还需要临时 ciphertext 生命周期和更复杂的并行调度，存储收益却与方案 A 基本
相同。因此不建议作为第一版。

**方案 D：跨层或跨输出通道共享 seed。**

不同层的权重数值没有稳定的空间周期或相同系数，跨层合并会破坏参数独立性；跨
输出通道合并又会改变现有通道映射。除非模型导出阶段能证明两个参数向量逐槽相同，
否则不能把它当作通用压缩方案。仅做字节级重复消除通常收益很小，不值得引入新的
参数寻址格式。

### 6.3 是否存在显著更优且简单的方案

没有一个同时满足“接近 `(8,8)` 的存储量、少于一次 mask 乘法、且不改变 CKKS
语义”的通用方案。选择性提取本身需要公开 mask 乘法；只用旋转和相加无法从一条
CKKS 密文中无损分离交错子网格。把 mask 加密也不会改善这一点，反而增加 bundle
大小并暴露更多结构。

在实现成本和收益之间，**方案 B 是明显更合适的第一版**：复用方案 A 的 seed
格式、runtime_lazy 映射、level/scale 规则和计费接口，只增加单轴间隔配置及单轴
复制循环。它的存储收益可能少于 `(a,b)`，但可以用一次或两次旋转快速验证数值和
耗时，再决定是否扩展到二维。

如果目标明确优先 bundle 大小，而能接受运行时成本，方案 A 的二维 `(2,2)` 是
更稳妥的默认值；它比 `(8,8)` 少 4 倍的复制旋转，仍能显著减少 seed 数量。建议
将间隔固定为少数白名单 `{(1,1),(2,1),(1,2),(2,2)}`，不要在第一版让 DP 搜索
任意 `(a,b)`。

### 6.4 最小实现路径

推荐按以下顺序实现和验收：

1. 仅覆盖普通 multiplexed、1×1、`n_packed_in_channel == 1`、无 external
   upsample、无 padding 边界的层；保持 3×3、depthwise、首层和 FC 不变。
2. 在现有 `weight_pt` 生成和 `runtime_lazy` manifest 中增加
   `seed_id/subgrid` 映射；不改 CKKS 参数集和主图 activation level。
3. 用现有公开 mask PT 乘法和 `rotate-and-add` 恢复子网格；种子使用 `L+1`，
   提取后 rescale 回 `L`，并把 mask/复制操作加入 layer op count 和 storage
   report。
4. 先固定 `(2,2)`，完成单层数值回归、ResNet/MobileNet 小图链路和 bundle 对比；
   再根据实测结果开放 `(2,1)` 或更大的间隔。
5. 只有当单层实测确认中间结果可安全复用时，才考虑方案 C；不把它作为基础依赖。

该路径没有证明二维交错在所有模型上都优于现有 periodic packing。它只说明：在
当前代码结构下，方案 A 的存储收益已经接近可达到的上限，而方案 B 的单轴限制是
更容易落地、风险更小的工程起点。
